# P1: Add durable caller request identity and explicit retry attempts

## Classification / priority
Confirmed contract gap; P1, first implementation slice. Ambiguous submit acknowledgement can duplicate implementation side effects.

## Evidence and failure scenario
`runtime/session/daemon.py::_DaemonContext` starts `next_id=1` each time; `_handle_connection(action="send")` assigns a fresh integer and ignores caller identity. `runtime/session/client.py::send_prompt` and `send_prompt_nowait` cannot supply a caller key. The blocking client drops the queued receipt on EOF/timeout. `runtime/session/daemon.py::_dispatch_prompt` retries classified failures with new task IDs and temporary artifact directories; the worker response discards attempt count and provider run references.
Read-only probe `audit/delegation-hardening/reproduce.py` submits the same prompt and caller key twice: IDs 1 and 2 are both queued; fresh context resets its counter to 1. A harness retry after an ACK is lost therefore cannot determine whether it resubmitted a write.
`runtime/invocation_runtime.py::run_invocations` and `run_invocation_workflow` remove old artifact directories for reused task IDs: existing task IDs are not idempotency keys. `tests/test_invocation_runtime.py` explicitly tests replacement behavior.

## Bounded change
Add an opt-in caller request key, immutable payload fingerprint, durable accepted receipt, and attempt identity to session submission. Persist acceptance before ACK. Same key/same input returns the original receipt; conflicting payload returns a structured conflict. Preserve the receipt on blocking-client timeout/disconnect. Carry an opaque GitHub ticket URL/reference through persisted request and attempt metadata. Record retries as attempts of one request and expose their outcomes; ambiguous writes require explicit retry authorization rather than claiming exactly-once side effects. Preserve legacy task-ID artifact replacement behavior outside this opt-in contract.

## Observable acceptance tests
- Fake dispatch counter remains one after lost ACK and resubmission, including daemon restart after persisted acceptance.
- Concurrent same-key submissions yield one accepted request; different payload with that key is rejected before dispatch.
- Two intentional retries share request identity and have distinct attempt IDs and inspectable outcomes.
- Simulated write followed by transport loss is reported as uncertain; no automatic duplicate write is launched without the defined retry policy.
- Blocking disconnect returns known request identity; ticket reference round-trips to receipt/metadata without GitHub mutation.

## Dependencies / exclusions
No implementation dependency; establishes identity/storage schema for draft 02. Coordinate storage changes with 02. Excludes universal exactly-once execution, changing all legacy task-ID semantics, GitHub API integration, and automatic retry of uncertain writes.
