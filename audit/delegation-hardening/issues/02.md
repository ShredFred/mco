# P1: Persist request lifecycle and make nowait results recoverable

## Classification / priority
Confirmed defects and durability gap; P1. Accepted work becomes unaccounted for after failure.

## Evidence and failure scenario
`runtime/session/daemon.py::_DaemonContext` holds queue, current request, and completed-results cache only in memory; `_MAX_COMPLETED_RESULTS=50`. `_handle_connection(action="result")` checks completed/running only, not queued. Cancel/shutdown drain paths set request results but do not put them in `completed_results`. `runtime/session/state.py` persists session summary and conversational history, not request lifecycle. `manager.py::resume_session` relaunches a daemon with preserved history, not the old queue/results.
Probe: accepted queued ID 1 returns `Request 1 not found`; draining it on cancel still returns not found. An injected `_dispatch_prompt` exception escapes `_worker_loop`, leaving `req.done` false and `current_request` set. The daemon listener can remain alive after its worker dies. `tests/test_session_bugfixes.py::test_worker_survives_cancel_runtime_error` defines a raising dispatch but sends only ping/shutdown, so does not exercise that failure.

## Bounded change
Use the request record introduced in 01 for queued/running/terminal/unknown states and retained result/artifact references. Return queued as pending, distinguish unknown ID from expired retention, and persist cancellation results too. Catch request execution failures at the worker boundary, finalize waiter/result state, and keep subsequent dispatch operational. Write records atomically; recover accepted queued work and mark interrupted running work unknown/reconciliation-required unless termination or completion is proven. Do not blindly replay interrupted writes. Keep provider evidence outside TemporaryDirectory cleanup when needed for reconciliation.

## Observable acceptance tests
- Queued, running, succeeded, failed, and cancelled IDs are distinguishable and queryable; nonexistent IDs report unknown.
- Inject dispatch/run/poll/persistence faults; affected callers get a bounded explicit result and the worker can process a later request (or reports degraded health if persistence is unavailable).
- Kill/restart a fake-backed daemon at acceptance, dispatch, and completion boundaries: no accepted ID disappears, and no uncertain write is silently replayed.
- Restart after completion and after queued cancellation retains terminal receipts and evidence paths.
- Exceed current 50-result limit; retention is explicit and an expired receipt cannot be confused with never accepted work.
- Strengthen the misleading worker-survival regression by actually submitting the request and checking the next request.

## Dependencies / exclusions
Depends on 01 identity/record schema; implement recovery incrementally. Excludes distributed queues, remote execution, automatic rollback, exactly-once provider writes, and history-based guesses of request success. Use deterministic fake adapters and bounded local fault injection, no paid providers.
