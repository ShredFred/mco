# P1: Verify daemon identity and separate liveness from completion evidence

## Classification / priority
Confirmed unsafe PID-only fallback and status ambiguity; P1. Reused PIDs can be mistaken for MCO-owned processes.

## Evidence and failure scenario
`runtime/session/manager.py::_is_pid_alive` uses `os.kill(pid,0)` only and maps all OSError to dead. `list_sessions`, `ensure_session`, and `resume_session` trust that result; `stop_session` sends SIGTERM to the stored PID when socket shutdown fails, then reports stopped immediately. Read-only mocked probe confirms an unverified PID reports active and fallback calls `os.kill(123456,15)`. No real signal was sent.
`runtime/session/daemon.py` ping answers pong without checking worker health. `runtime/adapters/shim.py::poll` returns EXPIRED/completed for a missing in-memory handle; existing completion booleans do not by themselves establish successful exit. Existing invocation runtime already requires SUCCEEDED and decodes provider transport, so do not weaken that behavior.

## Bounded change
Bind state/socket replies to a daemon incarnation token plus verifiable process identity. Refuse signals on identity mismatch or unverifiable ownership; return unknown/unreachable separately from exited. Make startup readiness require matching handshake/worker health, and shutdown ACK mean accepted until exit is observed. Request completion requires durable terminal evidence tied to the exact attempt; missing handles or inaccessible PIDs must not be promoted to success or proven exit.

## Observable acceptance tests
- Simulated PID reuse and socket identity mismatch neither report ready nor send a fallback signal.
- Permission-denied liveness probe reports unknown rather than crashed; ordinary dead PID remains distinguishable.
- Live listener with failed worker is unhealthy; ensure/resume cannot treat it as ready solely because PID exists.
- Shutdown ACK followed by a still-live child remains stopping/unknown until bounded verification completes.
- Fake exited-success, exited-failure, live, missing-handle, and stale terminal evidence stay distinct; stale attempt evidence never proves the replacement attempt completed.

## Dependencies / exclusions
Process identity fix can start independently; attempt completion linkage depends on 01/02. Coordinate with 03 cancellation receipts. Excludes remote process supervision and treating process exit as proof that requested product changes are correct. Preserve Windows behavior from local main when rebasing.
