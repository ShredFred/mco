# P1: Scope cancellation to request and attempt and retain its outcome

## Classification / priority
Confirmed queued-only cancellation defect and request-scoping gap; P1.

## Evidence and failure scenario
`runtime/session/client.py::cancel_session` sends only session-level `cancel`; CLI `runtime/cli.py` exposes only that operation. `runtime/session/daemon.py::_handle_connection(action="cancel")` returns early if no current request, leaving queued requests intact; otherwise it cancels the running request and drains every queued request. `_DaemonContext.cancel_event` is shared. Probe confirms queued-only cancel returns `cancelled:0` with two requests still queued; adding a current request makes cancellation drain all three. A delayed harness cancellation intended for an earlier attempt can affect newer work in that session.
`runtime/adapters/shim.py::cancel` already looks up the adapter run handle and uses process-group TERM/KILL on this POSIX branch. The missing capability is scoped lifecycle control, not an absence of process cancellation.

## Bounded change
Introduce explicit request/attempt cancellation with expected attempt identity and a separate documented cancel-all operation. Cancellation of queued-only work must work. Keep cancellation requested distinct from termination confirmed, persist queued cancellation outcomes, and prevent delayed cancellation from applying to a replacement attempt. Propagate adapter cancellation errors without claiming that child termination was proven.

## Observable acceptance tests
- Cancel queued B while A runs: A continues, B never dispatches, C remains queued; B result is cancelled.
- Cancel when only queued work exists cancels the selected request; explicit cancel-all drains all intended work.
- Delayed cancellation for attempt A1 cannot kill A2 or another request.
- Already terminal/unknown IDs return deterministic idempotent/no-such-request receipts.
- Fake cancel failure produces cancellation-requested/unknown termination evidence; success records the affected run and terminal confirmation.
- A local disposable child/process-group fixture verifies descendants are stopped and an unrelated sentinel survives; never signal real provider processes in tests.

## Dependencies / exclusions
Depends on 01 identities and 02 terminal record API; fixtures may be added before persistence lands. Excludes global process-name killing, rollback of edits, and redefining all session cancel callers without a migration path.
